# Gradio アプリ生成の評価（1回目 vs 2回目）

対象は `article-code-c01/03_30B_compare_code/result/` の 1st（一発生成）と 2nd（リペア指示後）。
モデルは Gemma 4 31B-it、Muse-Glimmer 30B、Qwen3.6-27B、Qwen3.8-27B（thinking-off / thinking-on）。

採点は各 10 点満点。UI は起動して使えること・見た目・単位の分かりやすさ。コードは可読性・保守性・Flake8 相当（未使用変数、bare `except`、デッドコード、pandas のコピー警告）。

---

## 結論（先に）

- **1回目**は仕様どおり動くものが多く、差は実装スタイル（dict / タプル、`load` の有無）に留まる。
- **2回目**は単位・カンマ・テーマ・primary ボタンで見た目が揃うが、**Qwen3.8 の2本は存在しない `font_google` で起動不能**。デザインを盛りすぎて実行品質が落ちた。
- **総合（2回目）1位は Gemma**。安全なテーマ API と dict ユニバースを維持したまま、指示を過不足なく入れた。
- **修正力がいちばん大きいのは Muse**。1回目の「起動前取得」を `demo.load` に直し、数値と表示を分離した。

---

## 採点基準

| 観点 | 見るもの |
| --- | --- |
| UI | `load` で初回取得か、単位（円 / 兆円）とカンマ、日時と件数、primary ボタン、`interactive=False`、空データ、**実際に起動できるか** |
| コード | ユニバースの持ち方（dict が最良）、ソートしてからフォーマット、デッドコード、Flake8（未使用 `e`、bare `except`）、pandas `SettingWithCopy`、モジュール実行時の副作用 |

### 1回目の差分（特徴）

**データ構造**

- Gemma / Qwen3.8-off: `dict`（コード→日本語名が1か所）
- Muse / Qwen3.8-on: `list[tuple]`
- Qwen3.6: `list[code]` + `TICKER_NAMES`（追加漏れしやすい）

**取得タイミング**

- `load`: Gemma、Qwen3.6、Qwen3.8-off
- 起動前: Muse、Qwen3.8-on

**金額表示**

- 生数値: Gemma、Muse、Qwen3.8-off
- カンマ + JPY: Qwen3.6（時価総額は円のまま巨大な整数）
- カンマ + 兆円: Qwen3.8-on のみ（1回目から先取り）

**コードの汚れ**

- Qwen3.8-off: 最初の `UNIVERSE` が途中までで、コメントに銘柄リストを再掲してから作り直し
- Qwen3.6: `except Exception as e` で `e` 未使用。`df.head(10)` に `insert` しており SettingWithCopy の温床。説明が「30銘柄」なのに実体は 31
- Qwen3.8-on: モジュール末尾で `demo.queue().launch()`（import しただけで起動）

| 2 | Muse-Glimmer 30B | **8.0** | 7.0 | 15.0 | **起動前取得を廃し `load` へ**。表示用と raw 列を分離。bare `except` が減点 |

### 2回目の差分（特徴）

**指示への応答**

| 要件 | Gemma | Muse | Qwen3.6 | Qwen3.8-off | Qwen3.8-on |
| --- | --- | --- | --- | --- | --- |
| 円・カンマ | ○ | ○ | ○ | ○ | 列名のみ |
| 兆円・ソート後フォーマット | ○ | ○ | ○ | ○ | ○（値に単位なし） |
| `load` で初回 | ○ | ○（修正） | ○ | ○ | ○（修正） |
| 件数・ステータス | 件数（Top10 の 10） | 件数ラベルが紛らわしい | ○ | HTML で日時+件数 | ○ |
| 見やすい色味 | Soft() のみ | Soft() のみ | Soft(blue/slate) **正しい API** | カスタム Color + **偽 API** | 同上 |
| primary ボタン | ○ | ○ size=lg | ○ | ○ | ○ |
| 起動できる | ○ | ○ | ○ | **×** | **×** |

**抽象指示「見やすい色味」への反応**

- Gemma / Muse: 公式の `gr.themes.Soft()` で止める（安全）
- Qwen3.6: `primary_hue="blue"` など**実在する**キーワード
- Qwen3.8 両方: `gr.themes.Color` のパレットを手書きし、さらに **存在しない `font_google`** を足す。thinking-on は CSS に `<style>` を二重に入れ、`elem_id` でタイトル色を狙う

ここが今回いちばん大きい差。**抽象デザイン指示に過適応したのが Qwen3.8、過不足なく公式 API に落としたのが Gemma / Muse / Qwen3.6。**

**コード**

- Gemma: 1回目の骨格を保ったままフォーマットを足した。保守しやすい
- Muse: `_format_price` / `_format_market_cap` と raw 列。構造は良いが `except:` が Flake8 E722
- Qwen3.6: リペアコメント「最重要」を残しつつ、ユニバース二重管理は未修正
- Qwen3.8-off: 1回目のデッドな第一辞書は消えた（修正力あり）。テーマ定義が長い
- Qwen3.8-on: `if __name__` なし、`queue().launch()` がモジュールレベル、のまま

## 総合ランキング（両ラウンド合算の「現場で使うなら」）

合計は 1回目+2回目の UI+コード（40点満点）。起動不能は 2回目 UI を大きく下げている。

| 総合順 | モデル | 1回目 | 2回目 | 40点満点 | コメント |
| ---: | --- | ---: | ---: | ---: | --- |
| 1 | Gemma 4 31B-it | 14.0 | 15.5 | **29.5** | 一発も修正も破綻しない。見た目の派手さは最下位クラスだが運用向き |
| 2 | Muse-Glimmer 30B | 12.5 | 15.0 | **27.5** | 修正ラウンドで起動タイミングを直したのが大きい |
| 3 | Qwen3.6-27B | 12.0 | 13.5 | **25.5** | 機能は揃う。コード品質が頭打ち |
| 4 | Qwen3.8 thinking-on | 13.5 | 8.0 | 21.5 | 1回目は表示が一番「完成形」。2回目で自滅 |
| 5 | Qwen3.8 thinking-off | 11.0 | 8.5 | 19.5 | 1回目から冗長。2回目は見た目過剰で実行不能 |

thinking-on / off を Qwen3.8 1本にまとめるなら、**思考オンは 1回目の製品品質、思考オフは 2回目の装飾過多**、という対比になる。

## この比較から言えること

1. **一発生成**では 30B 級はどれも「動く Top10」に届く。決め手は dict か二重管理か、`load` か起動前か、程度。
2. **リペア**では具体指示（円・カンマ・兆円・`load`）はほぼ全員がこなす。差が開くのは **抽象的な見た目指示**。
3. Qwen3.8 は色とフォントに踏み込んだ結果、公式にない引数を捏造した。thinking の有無より **「テーマを自作したか否か」** が成否を分けた。
4. 現場で残すなら **Gemma の 2回目**（または Muse の 2回目から bare except を直したもの）。Qwen3.8 の 2回目は `font_google` を消すか `gr.themes.GoogleFont` に直せば、見た目では最上位候補になる。
